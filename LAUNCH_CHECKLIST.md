# Tirith — Public Launch Checklist

## 1. Legal & Licensing

- [ ] Add `LICENSE` file (MIT) to repo root
- [ ] Verify `license: "MIT"` in `sdks/python/pyproject.toml` (already set)
- [ ] Verify `"license": "MIT"` in `sdks/typescript/package.json` (already set)
- [ ] Add license header or SPDX identifier to key source files (optional but common for Go projects)
- [ ] Decide on a copyright holder line (e.g., "Joe Davies" or "Tirith Contributors")

## 2. Repo Hygiene — Remove Private References

- [ ] Audit `go.mod` — module path is `github.com/joedaviesio/tirith` (fine if that's the public org)
- [ ] Audit `.goreleaser.yaml` — `joedaviesio/homebrew-tap` needs to be public or you need a separate tap repo
- [ ] Check `.github/workflows/release.yaml` for secrets that won't exist in a public repo (`HOMEBREW_TAP_TOKEN`)
- [ ] Scrub git history for any leaked API keys, tokens, or credentials (`git log -p | grep -i "sk-"` etc.)
  - Consider using [truffleHog](https://github.com/trufflesecurity/trufflehog) or `gitleaks` for automated scanning
  - If secrets are found: rotate them, then either rewrite history or start fresh
- [ ] Remove `frontend/.next/` build cache from tracking (it's in `.gitignore` but files exist in tree)
- [ ] Remove `frontend/out/` and `internal/dashboard/frontend/` build artifacts from git tracking — these are generated by `make frontend` and shouldn't be committed in a public repo (add to `.gitignore`, generate at build time via CI)
- [ ] Remove `CLAUDE.md` from the public repo or strip it to a contributor-facing version (it contains internal implementation notes)
- [ ] Remove `STATUS.md` and `TIRITH_ARCHITECTURE.md` if they contain internal planning — or clean them for public consumption
- [ ] Remove this file (`LAUNCH_CHECKLIST.md`) before going public

## 3. Documentation

- [ ] Write `README.md` with:
  - One-liner description + badge row (Go version, license, release)
  - 30-second quickstart (`brew install`, `tirith start`, `import tirith`)
  - The three integration paths (SDK wrapper, CLI wrapper, manual env var)
  - Dashboard screenshot or GIF
  - Supported providers (Anthropic now, OpenAI/Google planned)
  - Link to full docs or wiki
- [ ] Write `CONTRIBUTING.md` — how to build, test, submit PRs
- [ ] Write `CODE_OF_CONDUCT.md` (use Contributor Covenant or similar)
- [ ] Add issue templates (`.github/ISSUE_TEMPLATE/bug_report.md`, `feature_request.md`)
- [ ] Add PR template (`.github/PULL_REQUEST_TEMPLATE.md`)
- [ ] Add `SECURITY.md` — how to report vulnerabilities (email, not public issue)

## 4. CI / GitHub Actions

- [ ] Add CI workflow (`.github/workflows/ci.yaml`):
  - `go test ./...`
  - `golangci-lint run`
  - `cd sdks/python && pip install -e . && pytest`
  - `cd sdks/typescript && npm ci && npm test`
  - Build the binary (ensure it compiles on linux/darwin, amd64/arm64)
- [ ] Verify release workflow (`.github/workflows/release.yaml`) works with GoReleaser on tag push
- [ ] Set up required secrets in the public repo: `HOMEBREW_TAP_TOKEN`
- [ ] Consider adding a `GITHUB_TOKEN`-based release if you don't want a PAT

## 5. Package Distribution

### Homebrew (Go binary)
- [ ] Ensure `joedaviesio/homebrew-tap` repo is public
- [ ] Test `goreleaser release --snapshot --clean` locally
- [ ] Tag a release (`git tag v2.1.0 && git push --tags`) and confirm the bottle builds

### PyPI (Python SDK)
- [ ] Create PyPI account and project for `tirith`
- [ ] Add `Homepage` and `Repository` URLs to `pyproject.toml` `[project.urls]`
- [ ] Add a `sdks/python/README.md` for the PyPI listing
- [ ] Test `python -m build && twine check dist/*`
- [ ] Publish: `twine upload dist/*` (or automate via GitHub Actions on tag)

### npm (TypeScript SDK)
- [ ] Verify `tirith` package name is available on npm (or scope it `@tirith/sdk`)
- [ ] Add `"repository"`, `"homepage"`, `"bugs"` fields to `package.json`
- [ ] Add a `sdks/typescript/README.md` for the npm listing
- [ ] Test `npm pack --dry-run`
- [ ] Publish: `npm publish` (or automate via GitHub Actions on tag)

## 6. Code Quality Pre-Launch

- [ ] Run `go vet ./...` and `golangci-lint run` — fix all warnings
- [ ] Run `go test -race ./...` — ensure no data races
- [ ] Run Python tests: `cd sdks/python && pytest`
- [ ] Run TypeScript tests: `cd sdks/typescript && npm test`
- [ ] Review hardcoded ports (`5555`, `5556`) — document them clearly, ensure they're configurable
- [ ] Verify `tirith start` / `tirith stop` / `tirith report` / `tirith dashboard` all work cleanly from a fresh install
- [ ] Test the full flow: install binary, `tirith start`, `import tirith` in Python, make API call, `tirith report` shows it

## 7. GitHub Repo Settings

- [ ] Set repo to **Public**
- [ ] Write a short repo description + topics (`cli`, `ai`, `cost`, `observability`, `llm`, `anthropic`, `openai`)
- [ ] Set the default branch to `main`
- [ ] Enable Discussions (for community Q&A)
- [ ] Protect `main` branch (require PR reviews, CI passing)
- [ ] Disable wiki if you're not using it (reduces maintenance surface)
